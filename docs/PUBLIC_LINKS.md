# Ссылка на лендинг для стажёра

После публикации редактор может скопировать отдельную ссылку на готовую страницу.
Получателю не нужны учётная запись, приглашение или пароль. Ссылка открывает
только опубликованный лендинг; библиотека, редактор и управление сотрудниками
по-прежнему требуют входа.

## Как отправить страницу

1. Проверьте содержимое в Студии и нажмите «Опубликовать».
2. В блоке публикации нажмите «Скопировать ссылку» и отправьте её стажёру.
3. Для проверки откройте ссылку в приватном окне браузера, где вы не входили в Ленд.

Если браузер не разрешает автоматическое копирование, выделите адрес в поле
ссылки и скопируйте его вручную. Используйте адрес рабочего сервера: ссылка
на `localhost` или `127.0.0.1` работает только на вашем компьютере.

У ранее опубликованной страницы публичной ссылки может ещё не быть. В этом
случае выполните предложенное в блоке публикации действие для создания ссылки.
Проверьте страницу перед этим: операция публикует текущую сохранённую версию.

## Обновление и прекращение доступа

- Правки в Студии сохраняют черновик. По отправленной ссылке остаётся последняя
  опубликованная версия, пока редактор не обновит публикацию.
- Обновление публикации сохраняет публичную ссылку и меняет содержимое страницы.
- «Снять с публикации» закрывает публичную ссылку и убирает страницу из библиотеки.
- При повторной публикации после снятия создаётся новая публичная ссылка.
  Старую ссылку нужно заменить в сообщении стажёру.
- Внутренний адрес `/p/…` остаётся постоянным и доступен только после входа.

Любой, кому переслали публичную ссылку, сможет открыть эту страницу. Это общий
просмотр по ссылке, а не персональный доступ выбранного стажёра. Поисковым роботам
отправляется запрет индексации; он не заменяет пароль и не запрещает пересылку.

## Границы реализации

- Публичная страница `/s/<случайный адрес>` возвращает только HTML опубликованной
  версии. Нет списка проектов, соседних лендингов, данных учётной записи или API правки.
- Backend предоставляет один публичный GET `/api/v1/public/landings/<адрес>`.
  Все существующие маршруты библиотеки и студии сохраняют проверку сессии и роли.
- Адрес содержит 32 случайных байта в URL-safe формате. Он создаётся только
  при явной публикации; миграция не открывает ранее опубликованные материалы.
- HTML обслуживается без кэширования и с прежним CSP sandbox: скрипты и формы
  в опубликованном документе не исполняются. Публичный маршрут не передаёт
  сессию сотрудника backend и не выдаёт внутреннюю оболочку приложения.

## Выкладка и откат

Frontend и backend нужно обновлять вместе. До запуска новой backend-версии
сохраните согласованную резервную копию базы SQLite и файлов публикаций.
Миграция добавляет nullable-колонку и индекс, оставляя старые строки закрытыми.

После выкладки проверьте на учебной странице: публикация → копирование → открытие
без сессии → обновление → снятие → отказ по старому адресу. Отдельно проверьте,
что библиотека и редактор без сессии требуют входа, а закрытые API возвращают 401.

Старая версия backend откажется работать с более новой версией схемы. Для полного
отката остановите приложение и восстановите согласованный снимок базы и файлов
вместе с прежними образами; не откатывайте только код поверх обновлённой базы.
