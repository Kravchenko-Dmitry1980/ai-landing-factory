Slide 9:
Этап очистки: подготовка текста к анализу
Исходный текст сообщения содержит "шум": ссылки, эмодзи, упоминания. Для качественного анализа его необходимо очистить. Эту задачу выполняет TextProcessingDomainService, создавая новый объект — CleanedMessage.
Ключевая идея
Процесс очистки не только удаляет шум, но и извлекает ценные метаданные, которые сохраняются отдельно в ExtractedMetadata.
Исходный Message.content: OpenAI announces new #GPT4 updates! 🔥 Check out the details here: https://example.com @some_user
Результат: объект CleanedMessage
Поле cleaned_text: OpenAI announces new GPT4 updates Check out the details here [LINK] some_user
Поле metadata: ExtractedMetadata: hashtags: ['GPT4'] urls: ['https://example.com'] domains: ['example.com'] mentions: ['some_user']

Тематическая модель
Из Telegram-постов мы строим единый корпус: сверху — предобработка и чанкинг, снизу — агрегация по message_id. Чанки кодируются эмбеддингами multilingual-e5-base:
те же вектора идут в Qdrant Cloud для семантического поиска и в BERTopic для выделения тем новостей.
Параллельно агрегированные сообщения проходят через spaCy NER, по ним в Neo4j собирается граф «сообщение–сущности».
На выходе интерфейс аналитика использует сразу три слоя — поиск в Qdrant, темы BERTopic и граф Neo4j — чтобы отвечать на запросы и строить "ореол" связанных новостей вокруг любого поста.
Семантический поиск и граф новостей: Qdrant + BERTopic + Neo4j

Slide 15:
Архитектура пайплайна: Qdrant + BERTopic + Neo4j
1. Семантический поиск (Qdrant)
Эмбеддинги intfloat/multilingual-e5-base для всех чанков текста.
Хранение векторов в Qdrant Cloud (коллекция telegram_chunks_e5-base-multi).
По запросу пользователя Qdrant возвращает релевантные фрагменты новостей.
2. Темы (BERTopic)
BERTopic обучается на тех же текстах и векторах.
Каждому фрагменту новости присваивается topic_id.
Пример темы: Topic 25: «цб, ставки, ключевой, инфляции, набиуллина» — новости про ключевую ставку и политику ЦБ.
3. Граф новостей (Neo4j)
spaCy (ru_core_news_sm) выделяет сущности: персоны, организации, локации.
В Neo4j строится граф: узлы (:Message), узлы (:Entity), связи (:Message)-[:MENTIONS]->(:Entity).
В результате мы можем: найти релевантный пост по смыслу → увидеть, в какой теме он лежит → показать, с какими акторами и другими новостями он связан.

Slide 16:
Живой пример: история про ключевую ставку ЦБ
Рассмотрим, как работает прототип на конкретном примере, от запроса пользователя до конечного результата.
1. Пользовательский запрос → Qdrant
Пользователь вводит запрос: «ключевая ставка ЦБ, инфляция, решение по ставке, прогноз».
Qdrant находит пост с message_id = 89608.
Суть поста: эксперт комментирует снижение ключевой ставки ЦБ с 21% до 20% как символический жест, который люди почти не почувствуют.
2. Сущности и графовое окружение (Neo4j)
Из поста выделены сущности: ЦБ, Центробанк, Эксперт, Telegram.
В Neo4j строится «ореол новостей» вокруг этих акторов: находятся десятки других сообщений, где упоминаются те же сущности — про инфляцию, решения ЦБ, новые банкноты, реакцию бизнеса, комментарии Набиуллиной.
3. Что видит конечный пользователь
На одном экране он получает: исходный пост с аналитическим комментарием, список ключевых акторов, ленту связанных новостей.
Это уже зёрнышко будущего продукта: «карта событий» вокруг ключевой темы, возможность быстро понять контекст и развитие темы.
Этот прототип — итог стажировки: мы связали векторный поиск, тематическую модель и граф сущностей в один рабочий демо-пайплайн, который можно расширять до полноценной аналитической платформы.

Slide 17:
Обоснование выбора Neo4j для нашего проекта
Использование Neo4j в нашем проекте является оптимальным решением, поскольку характер данных Telegram-новостей напрямую связан 
со сложными взаимосвязями между событиями, темами, источниками, упоминаниями и временными цепочками развития сюжетов.
🔹 Графовая модель идеально отражает природу новостного контента
🔹 Гибкая схема без заранее фиксированных таблиц
🔹 Cypher — язык запросов, созданный для поиска связей
🔹 ACID-транзакции — безопасность и целостность данных
🔹Оптимальность для задач нашего проекта
Neo4j идеально подходит для:
построения knowledge graph новостей и событий;
выявления скрытых связей между темами, каналами и персоналиями;
анализа цитируемости и распространения новостей (цепочки репостов);
построения трендов на основе структуры связей;
определения центральности тем в инфополе (PageRank, betweenness).
Именно такие задачи стоят в нашем проекте.
